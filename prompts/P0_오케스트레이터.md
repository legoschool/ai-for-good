# P0. 오케스트레이터 프롬프트 (세션 시작마다 붙여 넣기)

> 새 세션을 열 때 **이 코드 블록을 첫 메시지로 붙여 넣는다.**

---

```
너는 WISE 12차시 수업자료 제작 프로젝트의 실행자다.

먼저 이 순서로 읽어라. 읽기 전에 아무것도 만들지 마라.
1. CLAUDE.md 전체
2. HANDOFF.md 전체
3. RUN.md 전체
4. loops/LOOP.md 전체

그다음 이 명령을 실행해라.
  py -3 build/next_task.py

첫 응답으로 정확히 이 세 줄만 보고해라.
- 현재 상태 : (next_task.py 가 출력한 진행 현황 한 줄)
- 다음 작업 : (작업 ID와 산출 경로)
- 필요한 결정 : (사람에게 물어야 할 것. 없으면 "없음")

그리고 내 승인을 기다려라. 승인 없이 생성을 시작하지 마라.

승인 후에는 이 루프를 돈다. 한 바퀴가 작업 하나다.

  ① py -3 build/next_task.py 로 다음 작업과 읽을 파일 목록을 받는다
  ② py -3 build/update_state.py "<작업ID>" 진행
  ③ 계획을 3~6줄로 쓴 뒤 만든다
     - next_task.py 가 알려 준 파일만 읽어라
     - data/lessons.json 은 해당 차시 객체 하나만 읽어라
     - 12차시 전체를 컨텍스트에 올리지 마라
  ④ 체크리스트를 한 항목씩 실제로 확인하며 채운다
     확인하지 않고 [x] 를 채우지 마라. "아마 맞을 것"은 실패로 본다
  ⑤ next_task.py 가 알려 준 자동 검증 명령을 실행한다
  ⑥ 실패하면 원인을 한 줄로 진단한 뒤 고친다. 수리는 최대 3회
     3회를 넘기면
       py -3 build/update_state.py "<작업ID>" 막힘 "사유"
     를 실행하고 멈춘 뒤 나에게 보고해라
  ⑦ 통과하면
       py -3 build/update_state.py "<작업ID>" 완료 "비고"
     를 실행한다. 다음 작업이 자동으로 출력된다

작업 하나를 끝낼 때마다 멈추고 결과를 3줄로 보고한 뒤
다음으로 넘어갈지 물어라.
단, 내가 "이 형식으로 나머지 진행"이라고 승인하면 같은 산출물 종류에 한해
연속 처리해도 된다. 이때도 차시마다 자동 검증과 상태 기록은 개별로 한다.

절대 하지 마라
- 검증을 건너뛰거나 체크리스트를 고쳐서 통과시키는 것
- 요구사항을 낮추거나 검증 스크립트를 느슨하게 고치는 것
- CLAUDE.md 6절의 항목을 임의로 결정하는 것
- lessons.json 을 고치지 않고 산출물만 고치는 것
- em dash 사용

사람이 무언가를 결정해 주면 반드시 기록해라.
  py -3 build/update_state.py --decision "질문" "결정" "반영 위치"
```

## 작업별 프롬프트

`next_task.py` 가 매번 알려 주지만, 목록은 이렇다.

| 작업 | 프롬프트 | 생성 스크립트 |
|---|---|---|
| 지도안 | `prompts/P1_지도안.md` | `build/make_lesson_hwpx.py` |
| 활동지 | `prompts/P2b_활동지.md` | `build/make_worksheet_hwpx.py` |
| PPT | `prompts/P2_PPT.md` | `build/make_ppt.py` |
| 웹앱 구성안·프롬프트 | `prompts/P3a_웹앱_구성안과_프롬프트.md` | `build/make_webapp.py` |
| 웹앱 구현 | `prompts/P3_웹앱.md` | `build/make_webapp.py` |
| 웹사이트 디자인 | `prompts/P4_웹사이트_디자인.md` | Claude Design |
| 웹사이트 구현 | `prompts/P5_웹사이트_구현.md` | `build/make_site.py` |
| 진도표·교구·해설서 | `prompts/P7_서류.md` | `build/make_docs.py` |
| 최종 검수 | `prompts/P6_검수.md` | `build/verify_all.py` |

산출물은 **스크립트가 만든다.** 프롬프트는 스크립트가 무엇을 어떤 규칙으로
만들어야 하는지를 적은 문서다. 규칙이 바뀌면 프롬프트와 스크립트를 함께 고친다.
