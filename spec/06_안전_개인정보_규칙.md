# spec/06. 안전과 개인정보 규칙

**이 문서는 다른 모든 요구사항보다 우선한다.**
충돌하면 이 문서가 이긴다. 초등학생이 쓰고 결과물이 외부에 공개되기 때문이다.

## 1. 수집하지 않는 것

- 실명, 학번, 생년월일, 연락처, 이메일, 주소
- 얼굴 사진, 음성, 영상
- 학생이 올린 파일 (업로드 기능을 만들지 않는다)

## 2. 수집하는 것

- 닉네임 (학생이 정한 별명)
- 모둠 이름
- 활동 응답 (payload)
- 방 코드와 제출 시각

닉네임에 실명을 쓰지 않도록 입력 안내에 적는다.

## 3. 저장과 삭제

- Firebase 실시간 DB `/wise/<slug>/<방코드>/` 아래로만 쓴다.
- 같은 기록을 Google Sheets 에 백업한다.
- **학년도 종료 후 `/wise` 경로를 삭제한다.**
- 백업 시트는 학급 단위 통계만 남기고 개별 행을 지운다.
- 분석은 학급 단위 통계만 쓴다. 개인을 특정하는 분석을 하지 않는다.

## 4. 공개

- 게시판(8차시)은 **교사 승인 후에만** 공개한다.
- 학생 얼굴·이름이 드러나는 자료를 올리지 않는다.
- 공개 배포물에는 재구성한 문장과 출처 표기만 싣는다.
- 공유 금지 표시가 있는 회의자료와 개인 응답이 담긴 델파이 조사지는 내부 참고용으로만 쓴다.

## 5. 심리·정서적 안전 (10차시)

10차시는 사용 습관을 묻는다. 정서적 어려움이 드러날 수 있다.

- **응답을 익명으로 처리한다.**
- **개별 학생을 특정하는 화면을 만들지 않는다.** 학급 익명 집계만 보여 준다.
- 모든 화면 하단에 문구를 고정한다.
  > 힘든 마음은 AI가 아니라 믿을 수 있는 어른에게 먼저 말해요.
- 사용량이 많은 학생을 지적하는 분위기가 되지 않게 한다.
- 도움이 필요해 보이는 학생은 수업 후 개별 면담으로 연결한다.

## 6. 도구 사용

- 생성형 이미지 도구는 **교사 계정으로만** 쓴다.
- 서비스별 사용 가능 연령을 수업 전에 확인한다.
- 학생이 실제 개인정보를 입력하지 않도록 활동 중에 계속 안내한다.
- 사람 얼굴이 담긴 사진을 학습 데이터로 쓰지 않는다.

## 7. 결정된 사항

| 번호 | 쟁점 | 결정 | 날짜 |
|---|---|---|---|
| Q1 | 학생 식별 방식 | 닉네임만 | 2026-08-18 |
| Q2 | 학급 코드 범위 | 학교별 분리 | 2026-08-18 |
| Q3 | 8차시 이미지 업로드 | 기능 없음. 인쇄물·교사 화면 공유로 대체 | 2026-08-18 |
| Q4 | 10차시 위험 신호 표시 | 익명 집계만 | 2026-08-18 |
| Q5 | 웹앱 데이터 저장 | Firebase 실시간 DB + Google Sheets 백업 | 2026-08-18 |

새 쟁점이 생기면 **보수적인 쪽으로 기본 구현**하고 사람에게 묻는다.
사람이 정하면 `py -3 build/update_state.py --decision` 으로 기록한다.
