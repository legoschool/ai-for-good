# spec/07. 웹앱 공통 사양

12개 차시 웹앱과 공통 설문 웹앱이 **모두 이 문서의 값을 그대로 쓴다.**
여기 적힌 값을 앱마다 다르게 쓰면 학급 코드가 어긋나고 백업이 흩어진다.

---

## 1. 배포 형태

- **Google Sites 소스 코드 삽입용 단일 HTML 파일**로 만든다. Apps Script 웹앱이 아니다.
- CSS와 JS를 전부 인라인한다. 외부 파일·CDN 참조를 두지 않는다.
- 파일 하나로 브라우저에서 바로 열려야 한다. 빌드 단계가 없다.
- 산출 경로 : `out/webapp/<LID>/index.html` (예: `out/webapp/L01/index.html`)

### 1-1. iframe 제약

- `window.top` 접근, `window.open`, `alert`·`confirm` 남용을 피한다.
- 페이지 body가 **가로로 스크롤되면 안 된다.** 넓은 표는 자체 `overflow-x:auto` 상자 안에서 스크롤한다.
- 높이는 콘텐츠에 맞춰 늘어나게 두고, 내부에 고정 높이 스크롤 영역을 두지 않는다.

### 1-2. Apps Script 함정

`Index.html`로 옮겨 붙일 가능성이 있으므로 **정규식에 역슬래시 이스케이프를 쓰지 않는다.**

| 쓰지 말 것 | 대신 쓸 것 |
|---|---|
| `\d` | `[0-9]` |
| `\s` | `[ \t\r\n]` |
| `\w` | `[A-Za-z0-9_]` |
| `\.` | `[.]` |

## 2. 참여 방식

- **방 코드 6자리 + 비밀번호 4자리 + 닉네임** 으로 입장한다.
- 방 코드는 교사가 만들고 화면에 크게 띄운다. **복사 버튼을 반드시 둔다.**
- 비밀번호 4자리는 다른 반 학생의 우연한 진입을 막는 용도다. 보안 장치가 아니다.
- **실명, 학번, 연락처, 이메일을 수집하지 않는다.** (결정 Q1)
- 방 코드는 **학교별로 분리**한다. (결정 Q2)
- 닉네임 중복은 **막지 않는다.** 같은 닉네임이면 기존 기록을 이어받아 재입장한다.
  중복을 막으면 학생이 새로고침 후 다시 들어오지 못한다.
- 교사가 화면을 닫아도 **방은 사라지지 않는다.** 방 상태는 서버에 남는다.
- **혼자 체험 경로**를 반드시 둔다. 방 코드 없이 `체험해 보기`로 들어가면 로컬에만 저장되고 서버에 쓰지 않는다.

## 3. 데이터 저장 (결정 Q5)

**Firebase 실시간 DB를 주 저장소로 쓰고, 같은 기록을 Google Sheets에 백업한다.**

### 3-1. Firebase 설정값

12개 앱이 이 값을 그대로 쓴다.

```js
  authDomain: "remind-c2610.firebaseapp.com",
  databaseURL: "https://remind-c2610-default-rtdb.firebaseio.com",
  projectId: "remind-c2610",

  appId: "1:306138692167:web:a0cde95f7bc9eb3f724f62",

```

- **Analytics를 붙이지 않는다.** `getAnalytics`를 호출하지 않는다.
  초등학생 대상이고 학교망에서 차단되는 경우가 있다. 수업에 필요하지도 않다.
- 이 프로젝트(`remind-c2610`)는 다른 용도로도 쓰이므로 **경로를 `/wise` 아래로 격리한다.**

### 3-2. SDK를 붙이는 방법

단일 HTML 파일이고 외부 CDN을 못 쓰므로 **Firebase REST API를 `fetch`로 직접 호출한다.**
SDK 번들을 인라인하지 않는다. 파일이 수백 KB로 불어나고 교사가 수정할 수 없게 된다.

```js
var DB = "https://remind-c2610-default-rtdb.firebaseio.com";

function dbPut(path, data) {
  return fetch(DB + "/wise/" + path + ".json", {
    method: "PUT",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(data)
  }).then(function (r) { return r.json(); });
}

function dbPush(path, data) {
  return fetch(DB + "/wise/" + path + ".json", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(data)
  }).then(function (r) { return r.json(); });
}

function dbGet(path) {
  return fetch(DB + "/wise/" + path + ".json").then(function (r) { return r.json(); });
}
```

실시간 갱신은 **3초 폴링**으로 한다. `EventSource`(SSE) 스트리밍은 학교망 프록시에서 자주 끊긴다.

```js
function dbWatch(path, onData) {
  function tick() { dbGet(path).then(onData).catch(function () {}); }
  tick();
  return setInterval(tick, 3000);
}
```

### 3-5. 보안 규칙

Firebase 콘솔의 실시간 데이터베이스 규칙에 아래를 넣는다.
**루트 읽기를 열지 않는다.** 방 코드를 아는 사람만 그 방을 읽고 쓴다.

```json
{
  "rules": {
    "wise": {
      "$app": {
        "$room": {
          ".read": "$room.length === 6",
          ".write": "$room.length === 6",
          ".validate": "newData.hasChildren(['meta']) || true"
        }
      }
    }
  }
}
```

## 4. Google Sheets 백업

### 4-1. 대상 시트

- 이름 : `2026. ai적정활용 티처스랩`
- ID : `1szLUD-hzMwQh7aaae5S9S7OS-hEXMEMj2Vhbd-hjjFM`
- URL : https://docs.google.com/spreadsheets/d/1szLUD-hzMwQh7aaae5S9S7OS-hEXMEMj2Vhbd-hjjFM/edit

### 4-2. 규칙

- **Firebase 쓰기가 먼저다.** Sheets 백업은 그 뒤에 부수적으로 보낸다.
- **백업 실패가 학생 화면을 막으면 안 된다.** `catch`로 삼키고 조용히 넘어간다.
- 실패한 레코드는 `localStorage`의 대기열에 쌓고 다음 제출 때 함께 다시 보낸다.
- `no-cors` 모드로 보낸다. 응답을 읽지 않는다. 읽으려 하면 CORS 오류로 콘솔이 더러워진다.

```js
var SHEET_ENDPOINT = "https://script.google.com/macros/s/<배포ID>/exec";

function sheetBackup(record) {
  try {
    var queue = JSON.parse(localStorage.getItem("wise_backup_queue") || "[]");
    queue.push(record);
    localStorage.setItem("wise_backup_queue", JSON.stringify(queue));
    fetch(SHEET_ENDPOINT, {
      method: "POST",
      mode: "no-cors",
      headers: { "Content-Type": "text/plain;charset=utf-8" },
      body: JSON.stringify({ rows: queue })
    }).then(function () {
      localStorage.setItem("wise_backup_queue", "[]");
    }).catch(function () {});
  } catch (e) {}
}
```

`Content-Type`을 `text/plain`으로 보내는 이유는 브라우저의 사전 요청(preflight)을 피하기 위해서다.
`application/json`으로 보내면 Apps Script가 OPTIONS 요청에 응답하지 못해 실패한다.

### 4-3. 시트에 붙일 Apps Script

시트에서 `확장 프로그램 → Apps Script`를 열고 아래 코드를 붙인 뒤,
`배포 → 새 배포 → 웹 앱`, 실행 계정은 `나`, 액세스 권한은 `모든 사용자`로 배포한다.
배포 URL을 위 `SHEET_ENDPOINT`에 넣는다.

```js
var HEADERS = ["받은시각", "앱", "방코드", "닉네임", "모둠", "제출시각", "내용"];

function doPost(e) {
  try {
    var body = JSON.parse(e.postData.contents);
    var rows = body.rows || [];
    var ss = SpreadsheetApp.getActiveSpreadsheet();
    var now = new Date();

    rows.forEach(function (r) {
      var sheet = ss.getSheetByName(r.app);
      if (!sheet) {
        sheet = ss.insertSheet(r.app);
        sheet.appendRow(HEADERS);
        sheet.setFrozenRows(1);
      }
      sheet.appendRow([
        now,
        r.app || "",
        r.room || "",
        r.nick || "",
        r.group || "",
        r.at ? new Date(r.at) : "",
        JSON.stringify(r.payload || {})
      ]);
    });

    return ContentService.createTextOutput(JSON.stringify({ ok: true, n: rows.length }))
      .setMimeType(ContentService.MimeType.JSON);
  } catch (err) {
    return ContentService.createTextOutput(JSON.stringify({ ok: false, error: String(err) }))
      .setMimeType(ContentService.MimeType.JSON);
  }
}

function doGet() {
  return ContentService.createTextOutput("wise backup endpoint");
}
```

앱 slug마다 시트 탭이 자동으로 생긴다. 탭 13개(차시 12 + survey)가 만들어진다.

## 5. 교사 대시보드

12개 앱이 모두 갖춰야 하는 화면이다.

| 기능 | 내용 |
|---|---|
| 방 만들기 | 6자리 코드 자동 생성 + **복사 버튼** + 비밀번호 4자리 지정 |
| 제출 현황 | 닉네임별 제출 여부, 미제출 인원 수 |
| 결과 집계 | 앱마다 다른 집계 화면 (분포 막대, 목록, 투표 결과) |
| 결과 띄우기 | 학급 화면에 결과만 크게 띄우는 발표 모드 |
| 내려받기 | 현재 방의 기록을 CSV로 내려받기 |
| 방 잠그기 | 더 이상 제출을 받지 않음 |

교사 화면은 방 코드와 비밀번호를 알아야 열린다. 별도 로그인을 두지 않는다.

## 6. 화면과 접근성

- 기본 글자 크기 16px 이상. 학생 입력 영역은 18px.
- 터치 대상 최소 44px × 44px. 태블릿에서 손가락으로 눌러야 한다.
- 색만으로 뜻을 구분하지 않는다. 4색 신호등은 색 + 글자(`그냥 써도 돼` 등)를 함께 쓴다.
- 다크 모드를 강제하지 않는다. 밝은 배경 하나로 통일한다. 교실 프로젝터에서 어두운 화면은 안 보인다.
- `prefers-reduced-motion`을 존중한다.

## 7. 안전 문구

**10차시 앱(`habit-check`)은 모든 화면 하단에 아래 문구를 고정한다.**

> 힘든 마음은 AI가 아니라 믿을 수 있는 어른에게 먼저 말해요.

나머지 앱은 입장 화면에 아래 문구를 둔다.

> 이름, 사진, 친구 이야기 같은 개인정보는 넣지 않아요.

## 8. 보관과 삭제

- 학년도 종료 후 Firebase 경로 `/wise`를 삭제한다.
- 백업 시트는 학급 단위 통계만 남기고 개별 행을 삭제한다.
- 분석은 학급 단위 통계만 쓴다. 개인을 특정하는 분석을 하지 않는다.
