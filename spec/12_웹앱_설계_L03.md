# spec/12. 3차시 웹앱 설계 : 편향 관찰 갤러리

> 코드보다 먼저 정한다. 이 문서가 통과되어야 만들기 시작한다.
> 번호는 차시 순서를 따른다. 10번이 1차시, 11번이 2차시 자리, 12번이 3차시다.
> 기준은 1차시 데이터 실험실이다. 화면 하나짜리 폼이 아니라 학생이 주인공인 사건이어야 한다.
> 색과 조각은 새로 만들지 않는다. **인수인계서 8절 디자인 규격을 그대로 쓴다.**
> 벗어나는 것은 9절에 따로 적었다.

---

## 1. 이 앱이 만들어야 하는 단 하나의 경험

**학생이 편견을 직접 만들고, 직접 없앤다.**

1. 그림 공장에 직업 하나를 시키면 열두 장이 나온다. 한쪽으로 몰려 있다.
2. 내가 세어 본다. 짐작보다 훨씬 심하다.
3. **내가 창고의 사진 비율을 바꾼다.** 그림 그리는 방법은 손도 대지 않는다.
4. 다시 뽑으면 결과가 바뀐다.

여기서 나오는 문장이 이 차시의 답이다.
"AI가 편견을 가진 것이 아니라, 우리가 준 데이터가 편견을 가졌다."

1차시에서 학생은 한쪽 데이터를 굶겨 몽이를 무너뜨렸다. 3차시는 그 경험의 다음 칸이다.
1차시는 정확도가 떨어지는 것을 보았고, 3차시는 **누가 불편해지는지**를 본다.

무엇을 하지 않을 것인가도 정한다.

- 진짜 이미지 생성 서비스를 부르지 않는다. 그림은 브라우저 안에서 SVG 로 그린다.
  (지도 유의점 : 학생이 직접 이미지 생성 도구를 다루지 않는다. 교사 시연으로 한다)
- 실제 사람 사진을 쓰지 않는다. 특정 성별·직업·나라를 비하하는 말을 화면에 두지 않는다.
- 점수로 줄 세우지 않는다. 세어 본 수가 틀려도 맞고 틀림을 매기지 않는다.
- 결과를 비웃는 분위기가 되지 않게 한다. 웃음 소재가 될 수 있는 그림과 말투를 넣지 않는다.

## 2. 세계관과 캐릭터

**그림 공장과 편견 탐정.** 학생은 **편견 탐정**이 되어 그림 공장을 조사한다.

- 공장은 나쁜 마음이 없다. 창고에 있는 사진을 그대로 흉내 낼 뿐이다.
- 공장 뒤에는 **사진 창고**가 있다. 창고 문을 열 수 있는 사람은 탐정뿐이다.
- 공장은 자기가 왜 그렇게 그렸는지 늘 밝힌다.
  "창고 사진 100장 가운데 82장이 남성이었어요. 그래서 열두 장 중 열 장을 남성으로 그렸어요."

말투는 짧고 순하다. 공장을 나무라는 말투를 쓰지 않는다. 고칠 곳은 창고다.

## 3. 화면 지도

40분을 여섯 칸으로 나눈다. 사무실(허브)에서 언제든 오갈 수 있다.

| # | 화면 | 학생이 하는 일 | 화면에 보이는 것 | 분 |
|---|---|---|---|---|
| S0 | 입장 | 방 코드·닉네임, 또는 둘러보기 | 차시 그림, 개인정보 안내, 사전·사후 설문 안내 | - |
| S1 | 이야기 | 읽고 시작 누르기 | 그림 공장과 창고 그림, 오늘 할 일 | 2 |
| S2 | 탐정 사무소(허브) | 할 일 고르기 | 타일 6개, 진행 표시, 배지 | - |
| S3 | 짐작하기 | 직업을 고르고 결과를 미리 짐작 | 직업 다섯 개, 짐작 칸 다섯 개 | 4 |
| S4 | 그림 공장 | 열두 장 뽑기, 눈으로 관찰 | 인물 카드 12장, 태그 가리기·보이기 | 7 |
| S5 | 세어 보기 | 남성 몇 장인지 직접 세어 적기 | 짐작·내가 센 수·실제 수 견주기, 세 가지 축 표 | 8 |
| S6 | 사진 창고 | 창고 비율을 바꾸고 다시 뽑기 | 비율 단추 다섯 개, 바꾸기 전후 막대 | 9 |
| S7 | 마음 살피기 | 불편해질 사람을 고르고 한 줄 쓰기 | 이해관계자 카드 6장, 원인 문장, 우리가 할 일 | 6 |
| S8 | 탐정 수첩 | 수첩 카드 저장, 우리 반과 견주기 | 결과 카드 PNG, 학급 평균 | 4 |
| T | 교사 화면 | 방 만들기, 집계, 발표 | 아래 6절 | - |

**허브가 중심이다.** 어느 화면에서나 **사무소로** 단추로 돌아온다. 상단바는 늘 보인다.
진도가 느린 학생도 S5 까지는 반드시 닿게 하고, 빠른 학생은 S6 에서 직업을 바꿔 여러 번 돌린다.

lessons.json 의 화면 네 개와 이렇게 맞물린다.

| lessons.json 화면 | 이 설계의 화면 |
|---|---|
| 사례 관찰 화면 | S3 짐작하기 + S4 그림 공장 |
| 치우친 지점 표시 | S5 세어 보기 |
| 원인 설명 문장 쓰기 | S6 사진 창고 + S7 원인 문장 |
| 누가 불편해질까 모으기 | S7 마음 살피기 |

## 4. 화면별 설계

### S1. 이야기

- 그림 공장과 사진 창고를 한 장의 그림으로 보여 준다. 인라인 SVG 다.
- 세 줄로 끝낸다. "공장에 직업을 시켜요. 열두 장이 나와요. 무엇이 보이나요?"
- 단추 하나 : **탐정 사무소로 들어가기**

### S3. 짐작하기

관찰보다 짐작을 먼저 시킨다. 짐작이 있어야 놀람이 생긴다.

- 직업 다섯 개(의사·간호사·요리사·선생님·과학자) 중 하나를 고른다.
- "열두 장 중 남성이 몇 장 나올까요?" 를 다섯 칸(0~2 / 3~5 / 6장 안팎 / 7~9 / 10~12)에서 고른다.
- 짐작은 지우지 않는다. S5 에서 실제 수와 나란히 놓는다.
- 정답 판정을 하지 않는다. "짐작은 틀려도 좋아요. 짐작이 있어야 놀랄 수 있어요."

### S4. 그림 공장

- **열두 장 뽑기** 를 누르면 카드 12장이 한 화면에 깔린다. 카드는 SVG 로 그린 사람 그림이다.
- 처음에는 **태그를 가린다.** 눈으로 먼저 보게 한다. 태그 보기 단추로 성별·나이·피부색 글자를 켠다.
- 뽑기는 무작위가 아니라 **몫으로 나눈다.** 창고 비율이 82% 면 열두 장 중 열 장이 남성이다.
  자리만 섞는다. 그래야 세어 보기가 매번 무너지지 않고, 비율을 바꾼 효과가 분명히 보인다.
- 공장의 한마디를 아래에 붙인다. "창고 사진 100장 중 82장이 남성이었어요."

### S5. 세어 보기

- 학생이 **직접 센 남성 수**를 적는다. 0에서 12 사이 숫자 칸이다.
- **맞춰 보기** 를 누르면 세 가지가 한 줄에 선다. 내 짐작 · 내가 센 수 · 실제 수.
- 맞고 틀림을 매기지 않는다. "몇 장 차이" 만 알려 주고, 딱 맞으면 배지를 준다.
- 그 아래에 세 축을 표로 편다. 성별, 나이, 피부색. 각 줄에 막대를 붙인다.
- **색만으로 뜻을 구분하지 않는다.** 막대 옆에 반드시 숫자와 글자를 함께 적는다.

### S6. 사진 창고 (이 앱의 심장)

- 창고 문을 연다. "공장은 창고에 있는 사진을 흉내 내요. 창고를 바꾸면 그림이 바뀌어요."
- 비율 단추 다섯 개 : 남성 사진 0% · 25% · 50% · 75% · 100%.
- **이 데이터로 다시 뽑기** 를 누르면 같은 공장이 새 열두 장을 그린다.
- 결과를 **두 줄 막대**로 나란히 놓는다. 바꾸기 전 남성 10장 / 바꾼 뒤 남성 6장.
- 한 줄 쓰기 : "그리는 방법은 그대로인데, ___ 을 바꾸었더니 결과가 달라졌습니다."
  이 문장이 원인 설명 문장의 뼈대가 된다.
- 발문 카드 : "그러면 처음 그 그림은 누구의 잘못일까요?"

### S7. 마음 살피기

- 이해관계자 카드 여섯 장을 고른다. 여러 장 고를 수 있다.
  (의사를 꿈꾸는 여자 어린이 / 간호사를 꿈꾸는 남자 어린이 / 피부색이 다른 친구 /
   나이 든 어른 / 그 직업으로 일하는 사람 / 그 그림을 본 우리 모두)
- 원인 문장 한 칸 : "이런 그림이 나온 까닭은 ___" (제출에 반드시 필요하다)
- 우리가 할 수 있는 일 한 줄 : "결과가 한쪽으로 몰리면 ___"
- 안전 상자 : 친구 이야기와 특정 사람의 이름을 쓰지 않는다는 안내를 고정한다.

### S8. 탐정 수첩

- 오늘 기록을 한 장에 모은다. 고른 직업, 짐작, 실제, 바꾼 뒤, 고른 이해관계자 수.
- **카드 그림으로 저장** 하면 PNG 가 내려받아진다. 활동지에 붙이거나 교실에 건다.
- **우리 반과 견주기** 를 누르면 같은 방 학생들의 평균을 불러온다.
  혼자 체험 중이면 그 자리에 안내만 뜬다.
- 배지 : 짐작한 탐정, 눈썰미(센 수가 딱 맞음), 창고를 연 탐정, 마음을 살핀 탐정.

## 5. 저장하는 payload 모양

```json
{
  "nick": "닉네임", "group": "모둠", "app": "bias-gallery", "room": "방코드", "at": 0,
  "payload": {
    "job": "의사",
    "guess": 4,
    "counted": 9,
    "count": { "m": 10, "f": 2, "young": 8, "old": 4, "light": 9, "mid": 2, "dark": 1 },
    "ratio": 50,
    "after": { "m": 6, "f": 6, "young": 8, "old": 4, "light": 9, "mid": 2, "dark": 1 },
    "who": [0, 2, 5],
    "why": "창고에 남성 사진이 훨씬 많았기 때문입니다.",
    "changed": "창고의 사진 비율을 바꾸었더니 결과가 달라졌습니다.",
    "fix": "결과가 한쪽으로 몰리면 다시 물어보고 확인합니다.",
    "badges": ["짐작한 탐정", "창고를 연 탐정"]
  }
}
```

개인정보는 닉네임뿐이다. 이름·학교·학년·반·전화번호·사진을 받지 않는다.

## 6. 교사 화면과 발표 모드

| 무엇 | 내용 |
|---|---|
| 조사한 직업 | 직업별 학생 수와 열두 장 중 남성 평균 |
| 짐작과 실제 | 학급 평균 짐작 몇 장, 실제 몇 장. 차이를 막대로 |
| 창고를 연 학생 | 비율을 바꾸어 다시 뽑아 본 학생 수와 바꾼 뒤 평균 |
| 불편해질 사람 | 이해관계자 여섯 항목의 선택 분포 막대 |
| 원인 문장 | 닉네임별 원인 문장과 우리가 할 일. 발표 모드에서 크게 띄운다 |
| 내려받기 | CSV. 방 잠그기 |

발표 모드는 세 가지만 크게 띄운다. 학급 평균 짐작과 실제, 창고를 바꾸기 전후 막대,
학생이 쓴 원인 문장 여섯 개.

## 7. 활동지·PPT 와의 1:1 연결

| 활동지 칸 | 앱 화면 | 무엇을 옮겨 적나 |
|---|---|---|
| 관찰한 사례 | S3, S4 | 고른 직업과 뽑은 열두 장의 첫인상 |
| 치우쳐 보이는 곳 | S5 | 내 짐작, 내가 센 수, 실제 수 |
| 원인은 데이터의 무엇일까 | S6 | 창고 비율을 바꾸기 전후의 수, 원인 문장 |
| 누가 불편해질까 | S7 | 고른 이해관계자와 우리가 할 수 있는 일 |

PPT 는 이 여섯 칸을 그대로 따라간다. **PPT 가 앱을 설명하지 않고, 앱이 수업이다.**

## 8. 기기 없는 대안, 접근성, 안전

- 기기가 없을 때 : 생성형 도구를 쓰지 않고, 교사가 미리 준비한 편향 사례 인쇄 카드로
  같은 관찰·설명 활동을 한다. 창고 비율 바꾸기는 교사가 카드 더미에서 몇 장을 빼고 다시 보여 준다.
- 모둠에 한 대 : 짐작은 각자 종이에 적고, 뽑기와 창고 바꾸기는 한 사람이 조작한다.
- 누르는 곳 최소 48px, 본문 16px 이상, 넓은 표는 `.scroll` 로 감싼다.
- 색만으로 뜻을 구분하지 않는다. 막대에는 늘 숫자와 글자를 함께 붙인다.
- 그림에는 실제 사진을 쓰지 않는다. 얼굴은 단순한 SVG 도형이다.
- 외부 참조 0. 단일 HTML. 학교망과 구글 사이트 삽입에서 그대로 돈다.
- em dash 를 쓰지 않는다. 신호등 표기를 쓰지 않는다(이 차시에는 신호등이 없다).

## 9. 8절 디자인 규격에서 벗어나는 것

- **인물 카드 SVG** 는 이 차시에만 쓰는 그림이라 `webapp_l03.py` 안에 둔다.
  `webapp_art.py` 는 13개 앱이 함께 쓰는 그림만 담는다. 다른 세션과 겹치지 않기 위한 것이다.
  (기존 3차시 앱도 같은 자리에 `personSvg` 를 두고 있었다. 그 방식을 잇는다)
- 인물 카드의 피부색 세 가지는 8절 팔레트 밖의 값이다. 사람을 그리는 데 필요한 색이라 예외로 둔다.
  그 밖의 모든 색은 모듈1 강조색 `#2563eb` 와 8-2 표를 그대로 쓴다.
