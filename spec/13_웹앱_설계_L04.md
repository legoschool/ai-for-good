# spec/13. 4차시 웹앱 설계 : 정보 지킴이 본부

> 코드보다 먼저 정한다. 이 문서가 통과되어야 만들기 시작한다.
> 폼 하나가 아니라 여정이다. 1차시 데이터 실험실, 6차시 판정소와 같은 결로 만든다.
> 색과 조각은 새로 만들지 않는다. **인수인계서 8절 디자인 규격을 그대로 따른다.**

---

## 1. 이 앱이 만들어야 하는 단 하나의 경험

**학생이 자기 정보를 실제로 흘려 본다. 그리고 되돌릴 수 없다는 것을 겪는다.**

1. 카드 24장을 내 감으로 나눈다. 이때는 아무도 정답을 알려 주지 않는다.
2. 나눈 뒤에 카드가 열린다. 내가 초록으로 보낸 카드가 사실은 빨간 카드였다는 것을 본다.
3. 빨간 카드는 **되돌리기 상자**로 들어간다. 상자는 열리지 않는다. 지워지지 않는 기록을 손으로 겪는다.
4. 그래서 마지막 발문 "한 번 넣은 정보는 다시 지울 수 있을까요"에 학생이 자기 경험으로 답한다.

무엇을 하지 않을 것인가도 정한다.

- 실제 개인정보를 한 글자도 입력받지 않는다. 카드는 미리 만든 24장뿐이다.
- 점수로 줄 세우지 않는다. 안전 감각 점수는 "다시 볼 카드"를 찾아 주는 도구다.
- 겁주기로 끝내지 않는다. 노랑 카드에 **조건**을 쓰게 해서 판단 기준으로 남긴다.
- 금지 목록을 만들지 않는다. 지킴이 수칙은 "어떻게 하면 되는가"로 쓴다.

---

## 2. 세계관과 캐릭터

**정보 지킴이 본부.** 학생은 오늘 새로 들어온 **새싹 지킴이**다.

- 본부에는 문이 세 개 있다. 초록문(그냥 보내도 되는 정보), 노랑문(조건을 지키면 되는 정보), 빨간문(보내면 안 되는 정보).
- 문 너머는 **AI 나라**다. 한 번 문을 넘어간 정보는 본부도 다시 데려오지 못한다.
- 안내를 맡은 캐릭터는 **지킴이 반장**이다. 정답을 먼저 말하지 않는다. 다 나눈 뒤에 문을 열어 보여 준다.

말투는 짧고 단단하다. 야단치지 않는다.
"이 카드는 빨간문으로 갔어요. 왜 위험한지 같이 볼까요."

---

## 3. 화면 지도

40분을 여섯 구역으로 나눈다. 허브(본부)에서 언제든 오갈 수 있다.

| # | 화면 | 학생이 하는 일 | 화면에 보이는 것 | 분 |
|---|---|---|---|---|
| S0 | 입장 | 방 번호·닉네임, 또는 둘러보기 | 4차시 그림, 오늘 할 일 | - |
| S1 | 이야기 | 읽고 본부로 들어가기 | 문 세 개, 새싹 지킴이 임명 | 2 |
| S2 | 본부(허브) | 구역 고르기 | 타일 6개, 진행 표시, 배지 | - |
| S3 | 훈련장 | 정보 종류 세 문제 | 보기 세 개, 바로 알려 주는 까닭 | 4 |
| S4 | 분류실 | 카드 24장을 문 세 개로 보냄 | 카드 한 장 크게, 확신도, 진행 막대 | 12 |
| S5 | 열람실 | 카드가 열린다. 놓친 카드의 까닭 고르기, 다시 판단 | 안전 감각 점수, 유형별 표, 되돌리기 상자 | 8 |
| S6 | 조건 작성소 | 노랑 카드에 조건 한 줄씩 | 노랑으로 보낸 카드 목록 | 4 |
| S7 | 우리 반과 견주기 | 학급 분포 보기 | 갈린 카드 표, 위험 카드 경고 | 4 |
| S8 | 수칙 회의실 | 지킴이 수칙 5개 정하기 | 보기 수칙 8개 + 직접 쓰기 2칸 | 5 |
| S9 | 지킴이 카드 | 결과 카드 PNG 저장 | 배지, 오늘의 기록 | 1 |
| T | 교사 화면 | 방 만들기, 집계, 발표 | 아래 6절 | - |

**허브가 중심이다.** 어느 화면에서나 `본부로` 버튼으로 돌아온다.
느린 학생도 분류실과 열람실까지는 반드시 닿게 하고, 빠른 학생은 조건 작성소와 수칙 회의실을 채운다.

---

## 4. 화면별 설계

### S3. 훈련장

정보에 종류가 있다는 것을 먼저 잡아 준다. 판단 활동의 준비 운동이다.

- 세 문제. 보기 세 개 중 하나를 고르면 바로 까닭을 알려 준다.
- 묻는 것 : 나를 알아보는 정보란 무엇인가, 다른 사람의 정보는 누가 정하는가, 한 번 넣은 정보는 지울 수 있는가.
- 세 문제를 다 맞히면 배지 `훈련 통과`.

### S4. 분류실

- 카드 24장. 한 번에 한 장, 유형 태그와 아이콘을 크게 보여 준다.
- 문 세 개 : 초록문(넣어도 돼) · 노랑문(조건을 지키면 돼) · 빨간문(넣으면 안 돼).
  **색만으로 구분하지 않는다.** 문 이름과 뜻을 글자로 함께 쓴다.
- 고르면 확신도를 함께 누른다(확실해요 / 헷갈려요). 확신도까지 누르면 다음 카드로 넘어간다.
- 앞 카드로 되돌아가 언제든 바꿀 수 있다.
- **여기서는 정답을 보여 주지 않는다.** 감으로 나눈 결과가 그대로 열람실의 재료가 된다.

### S5. 열람실 (이 앱의 심장)

- 카드가 열린다. 내 판단과 기준을 나란히 놓는다.
- **되돌리기 상자** : 내가 초록문이나 노랑문으로 보냈는데 기준은 빨간문인 카드를 상자에 담아 보여 준다.
  상자에는 자물쇠가 그려져 있고 "이미 넘어간 정보는 돌아오지 않아요" 한 줄이 붙는다.
- 놓친 카드마다 **왜 위험한지 까닭을 고른다.** 네 가지 중 하나다.
  나를 찾아낼 수 있어서 · 다른 사람의 것이라서 · 기록이 남아서 · 되돌릴 수 없어서.
  까닭을 고르면 카드의 설명이 열린다. 지도안 [활동 2] 근거 말하기가 이 화면이다.
- 유형별 표 : 나를 알아보는 것 / 있는 곳 / 다른 사람 / 기록으로 남는 것 / 이미 알려진 것.
  어떤 유형에서 자주 놓쳤는지 학생이 스스로 본다.
- **다시 판단하기** 버튼을 둔다. 바꾼 카드는 지우지 않고 `생각을 바꾼 카드`로 센다.
- 안전 감각 점수는 큰 숫자로 보여 주되, 아래에 한 줄을 붙인다.
  "이 점수는 내가 조심하는 정도를 보는 눈금이에요. 사람의 등급이 아니에요."

### S6. 조건 작성소

- 노랑문으로 보낸 카드마다 한 줄 칸이 열린다.
- 예시를 자리표시자로 넣는다. "예: 이름을 지우고 상황만 쓴다면"
- 금지형 문장(하지 마, 안 돼, 금지)이 들어가면 조건형으로 바꾸도록 안내한다. 막지는 않는다.
- 이 문장이 6차시 조건, 7차시 우리 반 약속의 재료가 된다.

### S7. 우리 반과 견주기

- 방 데이터를 읽어 카드별 분포를 표로 보여 준다.
- 의견이 갈린 카드를 위로 올린다. 기준이 빨강인데 초록으로 보낸 사람이 있는 카드는 따로 표시한다.
- 둘러보기(혼자 체험) 중에는 분포가 없다고 알리고 나머지 활동은 그대로 하게 한다.

### S8. 수칙 회의실

- 보기 수칙 8개를 준다. 전부 **조건형**이다. "이름 대신 별명을 쓴다", "친구 이야기는 넣지 않는다" 등.
- 다섯 개를 고르거나, 직접 쓰기 칸 두 개에 우리 모둠 말로 쓴다. 합쳐서 5개가 되면 회의 종료.
- 다섯 개를 채우면 배지 `수칙 다섯`. 지도안 [활동 3]과 활동지 4번 칸이 이 화면이다.

### S9. 지킴이 카드

- 닉네임, 판단한 카드 수, 안전 감각 점수, 되돌리기 상자에 담긴 카드 수, 수칙 첫 줄을 넣어 PNG로 저장한다.
- 배지 : `훈련 통과` · `카드 24장` · `까닭 대기` · `생각을 바꾼 용기` · `수칙 다섯`.
- 다음 차시 예고 한 줄 : "다음 시간부터는 AI를 언제 어디까지 쓸지 우리가 정해요."

## 5. 저장하는 payload

```json
{
  "nick": "닉네임", "group": "모둠", "app": "info-sorter", "room": "방코드", "at": 0,
  "payload": {
    "choice": { "0": "2", "1": "2" },
    "sure": { "0": "0", "1": "1" },
    "why": { "3": 1 },
    "cond": { "12": "이름을 지우고 상황만 쓴다면" },
    "rules": ["이름 대신 별명을 쓴다", "친구 이야기는 넣지 않는다"],
    "judged": 24, "hit": 19, "unsure": 5, "changed": 2, "leaked": 3,
    "quizOk": 3, "badges": ["훈련 통과", "카드 24장"]
  }
}
```

개인정보는 닉네임뿐이다. 실명·학교·학년·반·전화번호·사진을 받지 않는다.
자유 입력은 조건 한 줄과 수칙 두 줄뿐이고, 둘 다 실제 정보를 쓰지 말라고 화면에 적는다.

## 6. 교사 화면과 발표 모드

| 무엇 | 내용 |
|---|---|
| 학급 안전 감각 | 기준과 같게 판단한 비율. 개인 점수는 띄우지 않는다 |
| 카드별 분포 | 24장 각각 초록·노랑·빨강 인원수 |
| 위험 카드 경고 | 기준이 빨강인데 초록으로 보낸 인원이 있는 카드를 먼저 보여 준다 |
| 갈린 카드 | 한쪽으로 70%가 모이지 않은 카드 |
| 까닭 분포 | 네 가지 까닭을 고른 횟수. 막대로 본다 |
| 조건과 수칙 | 학생이 쓴 조건 문장과 수칙 목록. 학급 수칙을 여기서 뽑는다 |
| 발표 모드 | 갈린 카드 세 장과 학급 수칙 상위 다섯 개를 큰 글씨로 |
| 내려받기 | CSV. 방 잠그기 |

## 7. 활동지·PPT 와의 1:1 연결

| 활동지 칸 | 앱 화면 | 무엇을 옮겨 적나 |
|---|---|---|
| 1. 넣어도 되는 것 | S4 · S5 | 초록문으로 보낸 카드 이름 |
| 2. 조건을 지키면 되는 것 | S6 | 카드 이름과 내가 쓴 조건 한 줄 |
| 3. 넣으면 안 되는 것 | S5 | 되돌리기 상자에 담긴 카드와 그 까닭 |
| 4. 우리 모둠 개인정보 지킴이 수칙 5개 | S8 | 고른 수칙 다섯 줄 |

PPT는 이 여섯 구역을 그대로 따라간다. 앱이 수업이고 PPT는 발문만 띄운다.

## 8. 기기 없는 대안, 접근성, 안전

- 모둠에 한 대 : 카드는 모둠이 함께 정하고 한 사람이 누른다. 나머지는 인쇄 카드 24장을 손으로 나눈다.
- 한 대도 없을 때 : 인쇄 카드 24장과 모둠 분류판으로 같은 흐름을 간다. 교사 화면 한 대로 열람실을 시연한다.
- 누르는 곳 48px 이상, 본문 16px 이상. 색과 글자를 함께 쓴다.
- 움직임은 `prefers-reduced-motion` 을 존중한다.
- 단일 HTML, 외부 참조 없음. 학교망과 구글 사이트 삽입에서 그대로 돈다.
- 실제 개인정보 입력 금지 문구를 분류실과 조건 작성소에 고정한다.

## 9. 완료 정의 체크리스트

- [ ] 화면 아홉 개가 허브에서 오갈 수 있다
- [ ] 분류실에서는 정답이 보이지 않고, 열람실에서만 열린다
- [ ] 되돌리기 상자에 놓친 빨강 카드가 담기고, 담긴 수가 결과 카드에 남는다
- [ ] 놓친 카드마다 까닭을 고르면 설명이 열린다
- [ ] 다시 판단한 카드가 `생각을 바꾼 카드`로 세어진다
- [ ] 노랑 카드마다 조건 칸이 열린다
- [ ] 수칙 5개를 고르거나 써야 회의가 끝난다
- [ ] 지킴이 카드가 PNG 로 저장된다
- [ ] 교사 화면에 위험 카드 경고와 갈린 카드가 나온다
- [ ] 둘러보기 경로가 끝까지 막히지 않는다
- [ ] 스모크·실행·골격 동일성·전체 검사 통과, 외부 참조 0, 개인정보 입력 없음
