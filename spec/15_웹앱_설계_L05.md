## 1. 이 앱이 만들어야 하는 단 하나의 경험

**학생이 "대행"을 "보조"로 고쳐 본다.**

폼에 분류를 적어 내는 것이 아니라, 자기가 대행이라고 판정한 장면을
**조건 한 줄을 붙여 보조로 옮기는 일**을 직접 저지른다.

1. 같은 장면도 생각을 누가 했는지, 결과물을 누가 만들었는지에 따라 갈린다.
2. 우리 반의 판정이 서로 다르다는 것을 눈으로 본다.
3. 대행 장면도 조건을 붙이면 보조로 옮겨 간다. 그 조건이 6·7차시 약속의 재료가 된다.

무엇을 하지 않을 것인가.

- 정답 맞히기로 만들지 않는다. 두 축 값에 정답 표시를 붙이지 않는다.
- 점수로 줄 세우지 않는다. 판정한 장수와 조건 수만 센다.
- 자기 경험을 캐묻지 않는다. 카드로만 참여해도 끝까지 갈 수 있다.

## 2. 세계관과 캐릭터

**두바퀴 마을 자전거 정비소.** 도입 발문(보조바퀴와 대신 타 주는 사람)을 그대로 잇는다.

- 학생은 정비소의 **점검원**이다.
- AI 조수 로봇 **덜컹이**가 가게에 왔다. 덜컹이는 일을 잘하는데,
  자기가 도와준 것인지 대신해 준 것인지 스스로 모른다.
- 점검원이 장면 카드를 보고 판정해 주면 덜컹이가 배운다.
- 말투는 짧고 순하다. 덜컹이는 판정 뒤에 한 줄로 되받는다.
  "생각도 제가 했고 결과물도 제가 만들었네요. 대행이에요."

느린 학생도 S4까지는 닿게 하고, 빠른 학생은 S6에서 조건을 여러 장 쓴다.

## 4. 화면별 설계

### S3. 몸풀기 (보조바퀴 시험)

정답이 분명한 세 문제만 둔다. 판별대의 준비 운동이다.

1. 보조바퀴는 보조일까 대행일까 → 보조. 내가 페달을 밟기 때문이다.
2. 대신 타 주는 사람은 → 대행. 나는 타는 법을 못 배운다.
3. 보조와 대행을 가르는 것은 → 생각과 마지막 결정을 누가 했는가.

### S4. 판별대

- 장면 카드 12장. **인쇄 교구 「AI 활용 장면 카드 12장」과 글자까지 같다.**
- 축 두 개를 각각 칩 세 개로 고른다.
  - 생각은 누가 했나요 : 내가 · 반반 · AI가
  - 결과물은 누가 만들었나요 : 내가 · 반반 · AI가
- 두 축을 다 고르면 덜컹이가 되받는다. 합이 0~1 보조, 2~3 경계, 4 이상 대행.
  **이 판정은 이야기를 여는 기준이지 정답이 아니다.** 화면에 그렇게 적는다.
- 근거를 하나 고른다. 근거를 고르면 다음 카드로 넘어간다.
  근거 넷 : 내가 생각할 기회를 뺏기나 · 마지막 결정을 누가 하나 ·
  내가 배우는 데 도움이 되나 · 결과를 내 것이라 말할 수 있나
- 앞 카드·다음 카드로 오간다. 판정은 언제든 바꿀 수 있다.

### S5. 우리 반과 견주기

- 방에 모인 판정을 불러와 장면별 보조·경계·대행 수를 표로 보여 준다.
- 가장 많이 갈린 장면부터 위에 놓고 `갈림` 표시를 붙인다. 색만으로 표시하지 않는다.
- 혼자 체험 중에는 "우리 반 분포가 없어요"를 적고 나머지는 그대로 쓰게 한다.

### S6. 정비 작업대 (이 앱의 핵심)

- 경계·대행으로 판정된 장면만 목록에 올라온다.
- 각 장면에 "이렇게 하면 보조가 돼요" 조건을 한 줄 쓴다.
- 조건을 쓰면 그 장면이 **보조로 옮겨졌다**고 표시되고, 옮긴 장수가 올라간다.
  손에 잡히는 성과가 여기서 나온다.
- 예시문을 자리표시자로 준다. "내가 먼저 쓰고 다듬기만 맡긴다면"

### S7. 정비 수칙

- "어떤 경우에도 사람이 할 일" 후보 8개에서 **3개**를 고른다.
  무엇을 쓸지 정하기 · 사실인지 확인하기 · 마지막 결정하기 · 내 말로 다시 쓰기 ·
  누구에게 보일지 정하기 · 틀린 곳 고치기 · 마음을 살피기 · 출처를 밝히기
- 3개를 고르면 한 줄 쓰기 칸이 열린다. "AI에게 맡겨도 나는 ___ 만은 한다."
- 활동지 4번 칸과 그대로 맞물린다.

### S8. 점검원 카드

- 보조·경계·대행 장수를 막대로 보여 주고 조건으로 옮긴 장수를 적는다.
- **PNG 저장**. 활동지에 붙이거나 교실에 건다.
- 배지 : 판별사(6장 판정) · 근거왕(근거 6개) · 정비사(조건 3장) · 수칙 세움(3개 선택)
- 다음 차시 예고 한 줄 : "다음 시간에는 네 가지 신호로 더 자세히 나눠 봐요."

## 5. 저장하는 payload

```json
{
  "nick": "닉네임", "group": "", "app": "helper-or-doer", "room": "방코드", "at": 0,
  "payload": {
    "think": { "0": "2", "1": "0" },
    "make":  { "0": "2", "1": "0" },
    "why":   { "0": 1, "1": 2 },
    "cond":  { "0": "내가 먼저 쓰고 다듬기만 맡긴다면" },
    "zones": [3, 4, 5],
    "judged": 12,
    "fixed": 2,
    "rules": [0, 1, 2],
    "line": "AI에게 맡겨도 나는 마지막 결정만은 한다.",
    "quizOk": 3,
    "badges": ["판별사", "정비사"]
  }
}
```

개인정보는 닉네임뿐이다. 실명·학교·학년·반·전화번호·사진 칸을 만들지 않는다.

## 6. 교사 화면과 발표 모드

| 무엇 | 내용 |
|---|---|
| 요약 줄 | 판정 수, 조건으로 옮긴 장수, 수칙을 세운 학생 수 |
| 근거 분포 | 근거 네 가지를 막대로 |
| 장면별 표 | 보조·경계·대행 수와 `의견 갈림` 표시 |
| 조건 목록 | 닉네임·장면·조건 문장. 6차시 노랑불 조건의 재료 |
| 수칙 집계 | 후보 8개 중 학급이 많이 고른 순서 |
| 발표 모드 | 가장 갈린 장면 3개의 막대와 학생이 쓴 조건 문장 큰 글씨 |
| 내려받기 | CSV. 방 잠그기 (골격이 준다) |

개인 응답을 따로 지목하는 화면은 만들지 않는다. 조건 목록은 학생이 공개를 전제로 쓴 문장이다.

## 7. 활동지·PPT 와의 1:1 연결

| 활동지 칸 | 앱 화면 | 무엇을 옮겨 적나 |
|---|---|---|
| 1. 보조에 놓은 장면 | S4 | 보조로 판정한 장면 이름 |
| 2. 대행에 놓은 장면 | S4 | 대행으로 판정한 장면 이름 |
| 3. 가르는 기준은 무엇인가 | S4 근거 · S5 | 내가 고른 근거와 우리 반에서 갈린 장면 |
| 4. 사람이 꼭 할 일 3가지 | S7 | 고른 수칙 3개와 한 줄 |

PPT 는 이 흐름을 그대로 따라간다. **PPT 가 앱을 설명하지 않고, 앱이 수업이다.**

## 8. 기기 없는 대안, 접근성, 안전

- 모둠에 한 대 : 판정은 모둠이 함께 정하고 한 사람이 입력한다. 나머지는 활동지에 적는다.
- 한 대도 없을 때 : 인쇄 장면 카드 12장과 모둠 분류판으로 하고, 학급 집계는 칠판 스티커로 한다.
- 버튼 최소 48px, 본문 16px 이상, 색만으로 뜻을 구분하지 않는다.
- 단일 HTML. 외부 글꼴·이미지·CDN 을 부르지 않는다. ES5 로 쓴다.
- 자기 경험을 밝히기 어려운 학생은 카드 판정만으로 제출까지 갈 수 있다.
- 개인정보 안내와 사전·사후 설문 안내는 골격이 입장 화면에 고정해 둔다.
