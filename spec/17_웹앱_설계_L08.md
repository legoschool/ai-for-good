# spec/17. 8차시 웹앱 설계 : 약속 선포 게시판

> HANDOVER.md 8절 디자인 규격을 그대로 따른다. 모듈2 주황 `#d97706`.
> 8-7절 기다림 규칙(스피너·뼈대·버튼 잠금)을 쓴다.

---

## 1. 이 앱이 만들어야 하는 단 하나의 경험

**AI가 도운 결과물에 내 이름을 걸 수 있게 만든다.**

1. 사람이 할 일과 AI에게 맡길 일을 먼저 나눈다.
2. 캠페인 문구를 만든다. AI 초안이 있으면 **어디를 고쳤는지** 남긴다.
3. **활용 표기표를 채우지 않으면 게시되지 않는다.**
4. 교사가 승인해야 학급 게시판에 올라간다.

7차시에서 약속을 만들었다. 8차시는 그 약속을 **밖에 알리는 자리**이고,
알리는 순간 "이 결과물을 내가 설명할 수 있는가"가 바로 시험대에 오른다.

무엇을 하지 않을 것인가.

- **이미지 업로드 기능을 만들지 않는다.** (Q3 결정) 포스터는 종이나 교사 화면으로 본다.
  앱은 제목·문구·표기표 같은 글만 다룬다.
- 학생 얼굴·이름이 드러나는 자료를 올리지 않는다. 모둠 이름만 쓴다.
- 좋아요 수로 줄 세우지 않는다. 게시판은 겨루기가 아니라 알림판이다.

---

## 2. 세계관

**선포식 광장.** 모둠은 광장에 현수막을 내건다.

- 현수막은 세 칸을 채워야 올라간다. **역할 · 문구 · 표기.**
- 광장 관리인(교사)이 확인 도장을 찍어야 게시된다.
- 게시된 현수막은 다른 모둠이 읽고 **배운 점 한 줄**을 남길 수 있다.

## 3. 화면 지도

40분. 허브에서 오간다.

| # | 화면 | 학생이 하는 일 | 분 |
|---|---|---|---|
| S1 | 이야기 | 약속을 벽에 붙이기만 하면 아무도 안 읽는다는 장면 | 2 |
| S2 | 광장(허브) | 타일 5개, 현수막 완성도 표시, 배지 | - |
| S3 | 역할 나누기 | 여덟 가지 일을 사람·AI·둘 다로 나눈다. 결정은 사람이라는 기준을 확인 | 8 |
| S4 | 문구 공방 | 약속 8조항 중 하나를 고르고 제목·문구를 쓴다. 문구 틀 도우미 | 10 |
| S5 | 고친 곳 남기기 | AI 초안을 썼다면 어디를 어떻게 고쳤는지 기록. 안 썼으면 안 썼다고 표시 | 6 |
| S6 | 표기표 | 무엇을 AI로, 무엇을 사람이 했는지 표로 채운다. **비면 게시 불가** | 8 |
| S7 | 게시판 | 승인된 현수막을 읽고 배운 점 한 줄을 남긴다 | 6 |
| S8 | 현수막 카드 | 완성한 현수막을 PNG로 저장 | - |

## 4. 화면별 설계

### S3. 역할 나누기

여덟 가지 일 : 주제 정하기 / 자료 찾기 / 문구 초안 만들기 / 표현 다듬기 /
그림 아이디어 얻기 / 어떤 문구를 쓸지 고르기 / 사실 확인하기 / 결과에 책임지기.

- 사람 · AI · 둘 다 셋 중 하나를 고른다.
- **"고르기"와 "책임지기"를 AI로 두면** 화면이 되묻는다.
  "결정과 책임은 사람이 하기로 우리 반이 정했어요. 그대로 둘까요?"
  강제로 막지 않는다. 다시 생각할 기회만 준다.
- 다 나누면 사람 몫과 AI 몫의 비율 막대를 보여 준다.

### S4. 문구 공방

- 7차시 약속 8조항을 목록으로 준다. 하나를 고르면 그 조항이 현수막 주제가 된다.
- 제목(30자)과 문구(120자)를 쓴다.
- **문구 틀** 세 개를 준다. 누르면 빈 문구 칸에 넣어 준다.
  "___ 할 때는 ___ 하면 된다" / "우리 반은 ___ 를 먼저 한다" / "___ 대신 ___ 를 해 본다"
- 금지형 낱말(하지 마, 금지, 절대)이 들어가면 알려 준다. 7차시와 같은 기준이다.

### S5. 고친 곳 남기기

- 먼저 묻는다. **"AI 도움을 받았나요?"** 받지 않았으면 그대로 넘어간다.
- 받았으면 세 칸을 쓴다. AI가 준 문장 / 우리가 고친 문장 / 고친 까닭.
- 두 문장을 나란히 보여 주고 **바뀐 글자 비율**을 계산해 보여 준다.
  거의 그대로면 "고친 곳이 거의 없어요. 우리 말로 바꿔 볼까요?" 라고 알려 준다.

### S6. 표기표 (게시 조건)

네 줄을 채운다. 빈 줄이 있으면 게시 버튼이 잠긴다.

| 항목 | 예시 |
|---|---|
| 무엇을 AI로 만들었나 | 문구 초안 세 개 |
| 어떤 도구를 썼나 | 교사 계정 생성형 AI |
| 사람이 한 일 | 주제 정하기, 문구 고르기, 다듬기 |
| 확인한 사람 | 3모둠 전원과 선생님 |

- 다 채우면 **현수막 올리기** 버튼이 열린다. 누르면 제출되고 승인 대기가 된다.

### S7. 게시판

- `dbGet` 으로 같은 방의 제출을 불러온다. 스피너와 뼈대를 먼저 보여 준다.
- **승인된 것만 크게** 보여 준다. 승인 전은 "관리인 확인 중" 으로 흐리게 표시한다.
- 각 현수막에 **배운 점 한 줄**을 남긴다. 남긴 글은 votes 경로에 쌓는다.
- 교사 화면에서 승인 도장을 찍는다. (교사 화면 절 참고)

### S8. 현수막 카드

- 제목, 문구, 표기 요약, 모둠 이름을 넣어 PNG 로 저장한다. 인쇄해 교실에 붙인다.

## 5. 저장하는 것

```json
{ "payload": {
  "roles": { "0": "사람", "5": "사람", "7": "사람" },
  "pledgeNo": 2,
  "title": "생각이 먼저",
  "body": "숙제를 할 때는 내 생각을 먼저 쓰고 나서 도움을 받는다",
  "usedAi": true,
  "draft": "AI 초안 문장", "fixed": "우리가 고친 문장", "whyFix": "우리 반 말투로 바꿨다",
  "changed": 46,
  "credit": { "what": "문구 초안 세 개", "tool": "교사 계정 생성형 AI",
              "human": "주제 정하기, 고르기, 다듬기", "checked": "3모둠 전원과 선생님" },
  "notes": 2, "badges": ["역할 나눔", "표기 완료"] } }
```

승인 상태는 학생 payload 가 아니라 교사가 쓰는 `approve/<닉네임>` 경로에 둔다.
학생이 스스로 승인할 수 없어야 하기 때문이다.

---

## 6. 교사 화면

- 모둠별 현수막 목록 : 제목, 문구, 표기 4칸이 다 찼는지, 고친 비율
- **승인 도장** : 누르면 `approve/<닉네임>` 에 기록한다. 반려도 같은 자리에서 한다
- 표기 누락 경고를 맨 위에 모아 보여 준다
- 역할 나누기 집계 : "고르기"와 "책임지기"를 AI 로 둔 모둠 수
- 발표 모드 : 승인된 현수막을 큰 글씨로 넘기며 읽는다

| 활동지 칸 | 앱 화면 |

| AI 활용 표기표 | S6 |

---

## 8. 기기·접근성·안전

- 기기가 부족하면 손그림 포스터로 만들고 **표기표만 앱에 등록**한다. 대안 문구와 같다.
- 사진 업로드 칸이 없다는 것을 화면에 적는다.
- 게시판 글에는 모둠 이름만 쓴다. 닉네임은 교사 화면에서만 본다.
- 버튼 48px, 본문 16px, 색과 글자 병기.

## 9. 앞선 차시에서 나온 오류를 피한다

- **자리표시자 충돌** : slug 가 `pledge-board` 다. id·속성·클래스에 `pledge-board` 라는
  문자열을 쓰지 않는다. 앱 이름(약속 선포 게시판)과 부제도 마찬가지다.
  (1차시 `data-lab` 이 `data-label` 과 겹쳐 골격 검사가 갈라진 적이 있다.)
- **캔버스 없는 자리** : 막대는 `wiseBars` 로만 그린다. 직접 `getContext` 를 부르지 않는다.
- **자동 검사** : `activityAutofill()` 을 반드시 만든다. 여정형은 이것이 없으면 실행 검사가 막힌다.
- **기다림** : 게시판 불러오기와 승인은 `wiseSpinner` · `wiseSkeleton` · `wiseButtonBusy` 를 쓴다.
- **골격을 고치지 않는다.** 이 차시는 `build/webapp_l08.py` 하나만 만든다.
